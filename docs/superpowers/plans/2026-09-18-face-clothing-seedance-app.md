# Face and Clothing Seedance Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local FastAPI MVP that accepts a video file or video URL, anonymizes faces with ORB-HD/deface, accepts face/clothing references and a prompt, then sends the prepared assets to a configurable Seedance adapter and exposes job progress and a downloadable result.

**Architecture:** A small FastAPI app serves a browser UI and JSON API. An in-process background job runner keeps the local MVP dependency-light; the pipeline stages are isolated into input acquisition, deface processing, Seedance submission, and output publication. Seedance defaults to a transparent mock mode for local smoke tests and can be switched to an HTTP adapter through environment variables without changing the UI or job API.

**Tech Stack:** Python 3.11+, FastAPI, Uvicorn, Jinja2, Requests, yt-dlp, ORB-HD/deface CLI, FFmpeg supplied by deface/imageio-ffmpeg, plain HTML/CSS/JavaScript.

**Spec:** User-approved workflow in conversation: video file or Douyin link → face anonymization → face and clothing references → Seedance generation → local result.

## Global Constraints

- The default local mode must run without a Seedance API key by copying the defaced video as a clearly labelled mock result.
- Original uploads and intermediate files stay under the workspace `storage/` directory.
- Deface is invoked as an external CLI so its model and runtime remain replaceable.
- The application must never claim mock output was generated by Seedance.
- The real Seedance adapter must require explicit configuration and must not hard-code credentials.
