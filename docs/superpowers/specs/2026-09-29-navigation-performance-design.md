# 三个管理入口加载性能优化方案

状态：方案建议，尚未实施或发布。

## 目标与依据

目标是让“我的人物”“后台配置”“用户管理”在恢复草稿、查看视频和下载素材时仍能及时打开，同时保留草稿内容、现有生成行为和多用户隔离。

依据：[2026-09-29 排查记录](../../navigation-latency-investigation-20260929.md)。已复现同浏览器连接传输 8 MiB 素材时，人物页 8.68 秒、后台配置 4.60 秒、用户管理 10.55 秒的慢样本。独立连接传素材时，同期三页面约 0.10–0.46 秒。服务器本机健康检查保持毫秒级。另有个别网络尖峰，因此以下数字是待验收目标，不是效果承诺。

默认约束：优先利用现有服务器和存储，不以新增云服务支出作为第一阶段前提；保留当前账号、素材、草稿、任务和历史成片。

## 路线选择

| 路线 | 收益与限制 | 选择 |
|---|---|---|
| 只调整超时、加载提示和缓存 | 工作量较小，但大文件仍会占用连接；可能只是让失败更早显示 | 作为配套措施 |
| 减少原文件下载，再隔离媒体传输 | 对应已复现的触发条件；需调整素材状态和传输路径，可分两次发布 | 推荐 |
| 立即升级带宽或迁移全部媒体到对象存储/CDN | 可能改善容量，但有费用、访问控制和迁移工作；无法代替减少重复下载 | 作为容量复测后的扩展 |

## 第一阶段：消除不必要的大文件请求

### 1. 已有素材使用引用恢复

当前 `production.js` 将服务器素材完整下载为 Blob，再构造 File 填回文件输入框。改为区分两种素材状态：

- 本地新选择：保留真实 File，上传后绑定返回的素材 ID。
- 已存储素材：保留 ID、名称、类型、大小、校验值、预览地址和必要的媒体元数据，直接复用现有 ID。

恢复草稿、修改文字、保存草稿和提交生成都应直接使用已有 ID。只有确实需要在浏览器处理原始字节的编辑操作才读取原文件。保存时只上传新增或编辑后的文件。

需要同时调整 `hasSource`、生成按钮条件、参考素材计数、替换/移除、照片关联、草稿捕获和保存，不通过伪造零字节 File 兼容旧代码。沿用后端现有素材 ID 字段和草稿版本控制，避免改变历史任务快照。

### 2. 首屏只显示轻量预览

- 图片使用独立缩略图；设置 CSS 尺寸不能替代缩略图，因为原始字节仍会下载。
- 视频显示封面、名称、时长；用户点击播放后再设置视频源并支持 Range 读取。
- 隐藏的打码预览、关闭的播放器和未展开的历史任务详情不预加载原片。
- 预览图和元数据由上传/后台处理流程生成；旧素材未生成时先显示占位和已知信息，在后台补齐，不能在首屏 GET 中阻塞生成。
- 浏览器缺少时长时，显示待确认；最终生成前仍由服务端校验视频长度和模型限制。

验收重点：恢复一个含大视频、多张参考图的已有草稿，页面可用之前不请求任何完整原文件；不重新上传原有素材；保存和生成所引用的素材 ID 与原草稿一致。

### 3. 页面退出时释放无用读取

为预览、素材读取和列表查询绑定页面级取消信号。确认离开页面或关闭对应预览后取消读取、清除轮询，并释放对象 URL 和播放器资源。若用户取消离开，则保持编辑状态可用。

只取消可重试的读取；上传、保存和生成提交保留现有未保存保护、幂等和结果恢复机制。前端取消不等于已经撤销服务端业务操作。[AbortController 可中止 fetch、响应体消费与流读取。](https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort)

### 4. 三个入口按需要加载

| 页面 | 首屏必要内容 | 后续按需内容 |
|---|---|---|
| 我的人物 | 当前账户的人物统计或可见列表 | 已移除人物在展开时读取；云端状态与辅助信息独立加载，失败不遮住本地列表 |
| 后台配置 | 登录身份和配置概览 | 点击配置分类后读取该分类；去除重复模型配置请求 |
| 用户管理 | 登录身份和用户列表 | 身份确认后用户、任务、审计并行请求，各区独立展示；用户名映射到达后补齐，不以用户列表成功作为任务请求前置条件 |

受保护的数据仍在登录身份验证通过后加载。登录读取设置 8 秒总超时，超时显示“网络较慢，点击重试”，允许取消/重试。网络错误不被当作退出登录；只有真正的未授权响应触发重新登录。生成、创建用户等写操作不增加盲目自动重试。

## 第二阶段：隔离必须传输的大文件

### 默认落地方式

在现有服务器上增加专用 HTTPS 媒体入口，页面和 JSON API 使用当前入口，视频、原图和下载使用媒体入口。具体监听地址在实施时根据端口、证书和防火墙核实确定。

媒体请求先经过当前会话与租户归属校验，再由 Nginx 内部文件位置传输字节。可采用鉴权应用返回 `X-Accel-Redirect` 的方式；内部文件路径不得直接从公网访问。只开放需要的 GET/HEAD 读取路径，浏览器跨源请求只允许工作台来源。所有路径从服务端已经授权的素材记录映射，不接收任意文件系统路径。[Nginx 支持内部请求位置及 X-Accel-Redirect。](https://nginx.org/en/docs/http/ngx_http_core_module.html#internal)

验收必须在浏览器中核对实际网络连接已分离；不能只以“换了一个域名”判定完成，因为 HTTP/2 在满足条件时允许连接复用。[RFC 9113 §9.1.1](https://www.rfc-editor.org/rfc/rfc9113.html#section-9.1.1)

两个入口仍共享服务器公网带宽，连接隔离不等于带宽隔离。采用轻量预览、限制非交互媒体并发，并复测多人播放时的总出口吞吐；若剩余瓶颈确为总出口容量，再确定带宽调整或私有对象存储方案。

### 缓存与账号边界

第一阶段不依赖放开私有素材缓存获得性能收益。登录状态、后台配置和用户数据继续不缓存；带版本号的公共脚本和样式可独立设置缓存。

私有素材后续若采用 `private, no-cache` 与 ETag，必须先验证当前账号权限，再处理条件请求；包括 304 响应也不能越过鉴权。退出登录、切换账号、禁用账号后，新的素材请求不能获得旧账号数据。保留现有账号切换和浏览器历史恢复检查，不启用公共代理缓存存储私有媒体。`no-cache` 表示复用前验证，`no-store` 表示不存储，两者语义不同。[MDN HTTP 缓存说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)

TOS/CDN 是第二阶段之后的备选扩展，不直接复用当前提供给生成服务的长有效期签名链接作为管理页面访问凭据；另行定义账号归属、链接生命周期与撤销边界。

## 改动范围

| 位置 | 责任 |
|---|---|
| `app/static/production.js`，按需提取单独素材状态模块 | 已存储素材引用、本地文件上传、恢复/保存/生成的一致性 |
| `app/static/production-runs.js` 与制作页模板 | 视频按需加载、关闭/离页释放资源 |
| `app/production_router.py`、预览处理模块 | 轻量预览与媒体元数据、私有素材校验 |
| `app/static/account.js` | 登录请求超时、网络错误与会话失效区分 |
| `app/static/admin-settings.js`、`virtual-library.js`、`users.js` 及关联模型脚本 | 分区加载、请求去重、局部错误与取消 |
| `app/access_control.py`、部署目录中的 Nginx 配置 | 媒体入口鉴权、内部文件传输、精确响应头策略 |

实施前复核线上版本与本地差异；本表是设计范围，尚未修改这些文件。

## 验收标准

以下均为目标，以指定测试环境及网络条件为准，不承诺任意网络下固定耗时。

| 场景 | 目标 |
|---|---|
| 空闲进入三个入口 | 主要数据可用时间 P95 ≤ 1 秒 |
| 两个媒体读取同时进行、合计 8 MiB | 三个入口主要数据可用时间 P95 ≤ 2 秒 |
| 已有草稿恢复 | 可用前完整原文件读取数为 0；已存素材重复上传数为 0 |
| 登录请求无法完成 | 8 秒内给出可操作的超时反馈，不持续空转 |
| 同一浏览器退出 A、登录 B | 不能展示或重新读取 A 的人物、草稿、缩略图及原始素材 |
| 历史草稿与编辑链路 | 替换、移除、裁剪、保存、复制任务、生成引用保持正确；未保存内容保护有效 |

在隔离环境中，每个入口每种工况至少 30 次，报告中位数、P95、最大值、失败数和实际传输字节；覆盖冷缓存/热缓存、连续导航、慢网、素材下载、播放、普通用户和管理员。页面保持前台，并轮换测试顺序，让每个入口都承受相同的媒体传输窗口。统计超时和失败，不只统计成功请求。

生产环境进行有限流量的小样本复验，不将生产小样本描述成可靠 P95；不为性能验收触发收费视频生成。新实现必须通过既有草稿、素材编辑、人物库、账号隔离和任务提交测试。

## 可观测性、发布和回滚

先补齐请求 ID、路由模板、总请求耗时和上游耗时；前端分别记录导航、登录、主要数据可用时间。日志不写 Cookie、密钥、素材签名参数或完整私有 URL。这样能继续定位已观测到的零星尖峰。

第一版发布素材引用恢复、按需预览、读取取消、分区加载和必要计时；第二版发布媒体入口隔离。每版独立验收、独立回滚。第一版未通过原素材与草稿一致性测试时，不推进上线。

发布前保存当前版本、相关配置及数据库备份，确认处理队列状态；使用版本化静态资源避免新旧脚本混用。数据库如需新增元数据，只做兼容的增量变更。回滚切回旧应用版本和对应 Nginx 配置，保留新增期间的用户数据，不用整库恢复覆盖上线后任务。

建议执行顺序：记录基线 → 第一阶段本地回归和受控性能验收 → 第一版发布复核 → 媒体隔离对照验收 → 第二版发布复核 → 根据剩余尖峰决定是否需要带宽或对象存储投入。
