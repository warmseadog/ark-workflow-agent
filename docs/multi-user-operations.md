# 多用户工作台使用与运维

## 登录与首次使用

生产地址：`https://118.196.7.195:8443/login`。

初始管理员用户名为 `admin`，初始密码在首次部署时随机生成，保存在本机被 Git 忽略的 `storage/multiuser-admin-handoff.json`。如果你已修改密码，请使用修改后的密码，该文件不会自动更新。不要把该文件提交、截图或转发到公共群。当前版本不再要求首次登录强制改密；仍可主动修改密码，改密后可删除旧交付文件。

用户可在首页点击「注册」，或直接访问 `/register`，填写用户名、密码和确认密码，自助注册后直接进入工作台。用户名支持中文、字母、数字及 `. @ + _ -`，规范化后最多 64 个字符；忽略两端空格、大小写和全角／半角差异，重名会提示重新选择。密码长度为 6–1024 个字符，允许 6 位纯数字；两次输入须一致。当前采用用户名与密码注册，不要求邮箱、手机验证码或管理员审批。

自助注册账号固定为启用的普通用户，默认最多 8 个运行、10 个排队任务，不能通过注册指定角色或额度。账号及登录会话在同一事务内创建，密码使用 Argon2id 哈希保存，注册记录进入重要操作审计。每个来源 IP 在 15 分钟内最多进行 5 次通过基础字段校验的注册尝试，成功和用户名重复均计数；限流由数据库共享，重启或多个进程不能绕过。生产反向代理继续沿用现有可信代理设置。

自助注册随 `APP_AUTH_ENABLED=true` 的多用户模式开放；单用户模式不创建账号。首次部署仍须由运维初始化管理员，未初始化时注册会提示联系管理员，注册用户不会成为管理员或旧数据所有者。

管理员仍可在「用户管理」创建独立账户、选择角色、设置密码与额度。新用户和重置密码后的用户登录后直接进入工作台，不再被要求改密。忘记密码由管理员重置；重置、改密、禁用及角色变化都会撤销原会话。会话最长 12 小时；登录失败按用户名和来源 IP 限流。升级不会修改已有密码。

管理员可以创建管理员账号，也可以调整已有账号角色。普通用户不能管理人员、全局配置或他人的任务。系统至少保留一名已启用管理员，不允许将最后一名管理员降级或禁用。角色变化不会改变任务数据归属；新管理员可查看管理概览，但不会获得初始管理员旧全局接口的历史素材权限。

## 权限与数据边界

| 内容 | 普通用户 | 管理员 |
|---|---|---|
| 草稿、任务、素材、预览、生成结果 | 仅本人 | 本人；跨用户任务概览另有审计接口 |
| 人物与照片、官方认证会话 | 仅本人 | 本人；原有素材归初始管理员 |
| 模型、清晰度、时长选择 | 自己的草稿 | 自己的草稿 |
| 模型密钥、TOS、TikHub、打码默认值 | 不可修改 | 后台管理 |
| 系统提示词模板 | 可使用、另存为个人模板 | 在后台管理共享模板；制作页只读选用 |
| 个人提示词模板 | 仅本人编辑 | 本人编辑 |
| 创建/禁用/重置用户、角色、额度、审计 | 无权限 | 用户管理页面 |

模型服务商凭据仍由服务器统一保存，前端不获取密钥。普通用户不能全量枚举供应商云端人物或按任意云端 ID 导入他人的素材。

多用户模式仅允许抖音、小红书、快手和 B 站分享链接进入服务端解析；其他视频来源请先保存到本地再上传。不会让普通用户通过任意 URL 调用通用下载器访问服务器内网。

现有数据保留在原存储根目录，归初始管理员；新用户存储位于 `users/<服务端生成用户ID>/`，分别拥有 production.db、个人模板、人物认证会话、素材、缓存及结果。后台配置只从根目录加载，文件地址仍经过当前登录身份鉴权。

提示词模板明确区分共享与个人：原根目录中的模板继续作为共享模板保留，通过 `/api/admin/prompt-templates` 管理，每次操作重新检查当前账号是否为启用的管理员。所有登录用户（包括初始管理员）在制作页另存的新模板均保存在 `users/<用户ID>/local-preferences.db`，仅本人可修改。初始管理员的任务和素材仍保留原目录；降为普通用户后无法修改共享模板，仍可使用自己的个人模板。其他管理员也可以维护同一套共享模板。

管理员通过任务记录读取其他用户的成片、打码视频、播放文件和原始素材时，会记录 `view_user_media` 审计，包含操作者、所属用户、任务、资源及时间，并显示在重要审计中。同一操作者对同一用户、任务及资源的成功读取在 60 秒内合并一次，避免 HEAD 和视频分段请求刷屏；记录表示已允许读取，不表示整个文件已下载完成。拒绝请求、无效 Range 和不存在的资源不记作成功读取。任务列表轮询不增加此类记录。

## 调度与额度

- 全站默认最多同时执行 50 个视频生成任务（`APP_VIDEO_WORKERS` 可设为 1–50）。新注册用户默认最多 8 个运行、10 个等待；管理员在用户管理中可直接调整各账号额度，即时影响后续派发，但不会突破全局 50 个。降低额度不会中断正在执行的任务；已有账号额度在升级时保持不变。
- 按用户轮流取任务，禁用账户不再派发新任务；已经提交供应商的任务不强行终止，避免丢失付费结果。
- 预览处理单独限流：每人最多 2 个待处理/运行预览，全局最多 20 个。
- 外部打码与本地处理分别限流：外部打码默认最多 20 个同时执行，生产任务和预览共享此额度；本地裁剪、打码、兜底、MediaKit 结果解码校验与比例调整保持串行。同一租户、相同素材与参数的缓存只生成一次，其他任务等待后复用。
- 外部打码额度可通过 `APP_EXTERNAL_REDACTION_CONCURRENCY` 配置为 1–50，重启服务后生效。默认 20 来自 [MediaKit 项目与队列管理](https://docs.volcengine.com/docs/Intelligentprocessing/project-and-queue-management)（2026-10-07 核对）：所有项目和队列共享主账号的异步任务额度，更高额度须申请；如该账号还有其他应用调用 MediaKit，应预留它们的额度。API 请求频率与任务并发是不同限制，不能将 QPS 直接作为并发数。
- 重启恢复已有供应商 task_id 的任务；提交结果不明确时进入需要处理状态，不盲目重复发起付费生成。
- 数据独立不等于硬件独享。CPU、磁盘、网络与服务商并发额度仍共享。

统计页面显示提交数、成功/失败数、已知实际生成时长和本地媒体占用。不把模型请求时长、跟随源视频标记或猜测的价格当作实际结果。未取得实际时长的成功任务单独提示。这里没有积分、充值或计费功能。

## 任务命名与耗时

新建及复制为新草稿的任务默认使用北京时间 `YYYY-MM-DD HH:mm:ss`，例如 `2026-09-29 09:30:25`，可以手动改名。历史任务、原草稿和用户自定义名称不会因访问页面或升级而被重写。任务 ID 仍是独立随机 ID，同秒创建不影响隔离与幂等。

任务列表、详情及管理员概览区分“成片时长”和“任务耗时”。耗时保存在当前用户数据库的独立计时表中：

生成页活动任务约每 5 秒刷新；管理页当前列表含排队或运行中任务时约每 10 秒刷新，保持筛选、页码和人员编辑内容。隐藏页面暂停刷新，重新显示时读取最新记录；会话失效后停止刷新并要求重新登录。

- 排队耗时：任务处于 queued 状态的累计时间，含恢复后的重新排队。
- 执行耗时：任务处于 running 状态的累计时间，含素材准备、提交、查询、下载等本地执行阶段，不只是供应商推理时间。
- 总耗时：自任务提交至停止的墙钟时间；运行时随刷新增长，停止后冻结。继续恢复时会包含两次执行之间的暂停等待，并单独记录暂停耗时。
- 成功、失败、取消记录结束时间；需要人工处理时暂停计时，继续后恢复。服务异常重启无法确定中断运行片段的准确结束时刻时，执行耗时显示未知，不把停机时间伪装为执行耗时。
- 旧任务没有独立起止记录时显示“未记录／—”，不会用最后更新时间猜测。已有历史任务的媒体与名称不变。

## 配置与启动

生产必须设置：

```dotenv
APP_AUTH_ENABLED=true
APP_COOKIE_SECURE=true
APP_PUBLIC_ORIGIN=https://118.196.7.195:8443
```

`APP_AUTH_ENABLED` 关闭仅用于本地单用户兼容测试；不得将关闭认证的实例直接公开。数据库为空且认证开启时，所有工作区接口仍拒绝匿名访问，不提供公网初始化管理员入口。

全新独立安装可在服务器受控终端运行 `python -m app.manage_users init-admin --username admin`，交互输入初始密码。已存在的管理员不会被覆盖。不要使用命令行参数传密码，以免进入 shell 历史或进程列表。

Nginx 保留外部 Origin，应用严格校验；Uvicorn 仅信任 `127.0.0.1` 代理传来的来源地址，用于独立 IP 限流。保留单 Uvicorn worker，生产队列通过根目录文件锁避免重复派发。公开官方认证回调和短期模型取视频地址使用随机能力令牌，并关闭对应代理访问日志。

## 部署与回退

首次多用户迁移的历史驱动为 `deploy/ecs/release-multiuser.py`，只适用于其写明的旧基线，不能在当前版本重复运行。当前账户策略与耗时增量发布使用 `deploy/ecs/release-account-policy.py check|deploy|verify`，仅针对 ECS-YRXT 的方舟服务：比对已知线上基线、确认全部用户队列空闲、备份根目录及每位用户数据库与配置，保留旧 release。

增量切换前，在独立临时数据库运行真实登录、六位密码、角色创建、时间命名和耗时记录自检；STORAGE_DIR、WORKFLOW_DB、WORKFLOW_STORAGE 和 DATABASE_URL 都指向临时目录，不触碰生产密码，也不发起付费生成。实际 WORKFLOW_DB 纳入备份，旧 stage_tasks 的 queued/running 状态同样阻止发布。

切换使用短暂维护窗口：仅方舟 8443 入口暂时返回 503，待旧代理请求排空后才停止应用；另一个 443 网站保持原配置。内部健康、匿名拒绝、文件一致性及旧记录保留（仅解除强制改密标记）验证通过后，恢复 Nginx 原文件并开放入口，不改环境变量或 service。失败且无新任务时恢复旧代码；如果已有新任务，不自动回退，以免丢失结果。账号数据库和新增计时表不会被自动删除。

后续回退到不支持多用户的旧代码必须先暂停入口并检查全部用户队列，并恢复共享认证保护；不能仅切换代码软链接。备份含密钥和任务私有快照，应保持仅运维可读，不能放入 Git。
