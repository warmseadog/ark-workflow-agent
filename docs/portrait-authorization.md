# 真人认证：自动二维码（服务器版）

2026-09-27 已上线到 https://118.196.7.195:8443/ 。点击“真人认证”自动创建官方 CreateVisualValidateSession 会话并显示二维码，无需打开控制台复制链接。当前有效项目为 default；原 demo 项目不存在，已更正。登录方式保持原样。

本人用手机扫码，在官方 H5 完成认证后点击“完成”。手机返回工作台的专用页面，电脑每 5 秒查询状态；服务端调用 GetVisualValidateResult 确认后才显示认证通过。显示二维码或收到 resultCode=10000 都不能单独授予图片授权。

- 二维码有效期 30 分钟；关闭、重新打开及同一标签页刷新会恢复已有会话。
- “重新获取二维码”使旧本地扫描入口失效，并创建新会话。
- 浏览器仅保存幂等请求标识，不保存 BytedToken 或 H5 链接。
- 凭证仅在服务器 data/private/portrait-sessions.db 中持久化，已过期会话不再提供扫码入口；过期/失败/通过后清除对应凭证。
- /auth/portrait/scan、return、done 是手机专用公开路径；随机状态及官方凭证匹配后才接收返回，不能访问管理接口。普通 API、二维码读取和任务仍需工作台密码。
- Nginx 对这些敏感路径关闭访问日志，并抑制可能包含返回参数的 upstream 错误日志；Uvicorn 不记录访问日志。
- 无公网地址配置的本机实例保留手动邀约链接模式。服务器设置 PORTRAIT_PUBLIC_BASE_URL=https://118.196.7.195:8443。

验证：294 项 pytest 通过；1440/390 浏览器自动取码、重复打开、刷新、重新获取与认证状态测试通过；真实公网浏览器点击得到官方二维码、无 JS 错误，手机返回页无需工作台密码，管理接口仍要求密码。没有保存真实二维码截图，也没有代替用户完成人脸认证。

认证通过只证明官方真人认证完成。仍须有已通过官方素材校验（Active）的图片才能作为已授权人物导入；现有导入会重新核实项目、素材组及素材状态。

以下为最初本地手动模式说明：

# 真人照片认证与授权素材

本地工作台接入火山方舟的真人素材库。当前未配置公网返回页，因此使用“官方控制台邀约认证 + 本地同步素材”的方式，不自行判定人脸认证通过。

## 使用步骤

1. 在人物参考图区域点击“真人认证”，打开官方方舟体验中心。
2. 在官方真人人像素材管理中创建资产组/邀约，由照片本人完成官方要求的登录、真人认证、授权和照片上传。具体以控制台流程为准。
3. 如果官方提供邀约链接，可复制完整 HTTPS 链接回到本地弹窗生成二维码，发送给照片本人扫码。二维码仅编码官方链接，并不等于认证成功；本地不会保存活体视频或人脸特征。
4. 在官方控制台完成必要的授权接收和素材处理后，回到本地点击刷新授权素材。
5. 选择可用人物图片并导入。工作台下载的就是该官方图片，替换人物主参考；刷新页面会恢复，生成时以官方 asset:// 编号提交。

## 状态与限制

素材必须属于配置账号、项目中的 LivenessFace 真人素材组，并且状态为 Active、类型为 Image。普通本地上传的照片不会被自动标记为已认证。新增其他照片应先按官方流程校验入库，再同步导入。

提交生成和排队任务实际执行前都会向官方重新查询可用性。更改 AK/SK 或项目后，应重新同步选用素材。复用同一人物素材无需每次重新扫码；已失效、撤回或删除的素材不能继续新建生成。

官方 API Key 和 AK/SK 用途不同。此功能在高级设置中使用火山 Access Key / Secret Key，可明确选择使用项目现有的 TOS 凭据；相同凭据仍需拥有 Ark 素材查询权限。密钥仅保存在服务端，表单不回显。

没有公网返回页时，本地不会创建需要回调的自动认证会话，也不会伪造扫码状态；需要在官方页面完成，再手动刷新素材。今后接入公网 HTTPS 返回页后，可扩展自动会话与结果同步，仍须由后端向官方核实结果。

## 数据与测试

官方临时素材 URL 不返回给前端或保存为长期身份，长期关联保存官方素材编号和项目。下载固定至核实过的官方 HTTPS 素材域名，验证公网 IP、文件格式与大小，并支持现有 Fake-IP 解析流程。

本地生成二维码不调用认证收费接口。模型生成的计费和内容审核仍按实际官方服务执行。程序测试使用模拟素材和模拟模型，没有提交真人认证或新视频生成。
