# 虚拟人物自动入库与生成

2026-09-28，本地实现。配套设计见 [设计方案](superpowers/specs/2026-09-28-auto-virtual-person-design.md)，执行记录见 [实施计划](superpowers/plans/2026-09-28-auto-virtual-person.md)。

## 用户流程

新建草稿默认选择“上传虚拟人物”。用户上传人物图片或人物视频，补齐动作视频、衣服等素材，点击一次“生成视频”。任务自动创建或复用虚拟人物，提交官方素材，等待素材可用，然后继续原有生成流程。无需提前打开管理页建人物、选择新入库照片或再次提交生成。

这里保留一次明确的生成提交；仅选择文件、编辑参考图或打开草稿不会自动提交视频生成。

人物准备期间，任务列表显示进度。可恢复的异常提供“重新检查人物准备”，继续检查原人物和素材记录。确定的素材拒绝需要替换素材后重新提交。入库解析出人物后，人物选择器自动刷新目录，不改变当前草稿或人物选择。

## 与原流程兼容

| 输入 | 行为 |
| --- | --- |
| 新版页面新草稿 | `auto_virtual`：自动入库虚拟人物后生成 |
| 明确从人物库选择 | `existing_person`：按服务端记录使用真人或虚拟人物 |
| 真人授权 | 保留原有后台入口和官方授权、照片检查流程 |
| 旧草稿或旧客户端未传策略 | 有人物或官方绑定时继续检查官方素材；其他输入保持旧普通图片语义 |
| 已经提交服务商的视频任务 | 继续查询或下载原任务，不重新入库；不依赖原本地素材仍存在 |

`person_input_policy` 与图片/视频类型 `person_reference_mode` 分开保存。库中只有一个真人时，新草稿也不会自动选中该真人。自动模式不代表系统已识别图片一定是虚拟人，也不会将已绑定真人的素材改标为 AIGC；不兼容的真人、隐藏人物、跨账号或冲突关联会明确报错。

## 配置与限制

- 自动模式需要配置火山官方模型接口、人物素材服务凭据，以及已启用的 TOS。缺失配置会在提交阶段返回具体错误。
- 人物视频继续沿用 Seedance 2.0 与既有格式、时长、大小和合计时长限制。参考图片数量限制也保持生效。
- 精确复用依据当前账号/项目、文件 SHA-256 和素材类型；不同图片即便看起来是同一人也不会自动合并。后续要为同一人物补充不同素材时，可明确从库中选择该人物。
- 自动入库不省略官方素材检查；被拒绝后不会偷偷退回原图生成。
- 单轮人物准备最多等待 30 分钟。可恢复异常的再次检查复用原关联，不新建一套视频任务。

## 实现位置与持久化

`app/person_preparation.py` 负责本地预校验和任务内的人物准备。提交接口先在 SQLite 事务内冻结草稿与准备意图，后台才创建远程人物或入库素材；版本冲突、重复提交不会提前触发远程创建。

新增 `production_person_preparations` 保存每个生成任务的准备状态、已解析人物、照片任务映射、检查时间和重试信息，不回写不可变的 `run.snapshot`。公开 API 只返回 `state`、`person_id`、`message` 和可重试标志，凭据仍在现有私有配置快照中。

人物库沿用原有 `portrait_group_requests`，补充稳定请求标识与远程组 ID 检查点。创建结果不确定时，只对原结果作核实，不盲目再次创建。照片入库沿用原 worker，新增持久化的错误可重试属性。SQLite 表和列在原初始化入口增量创建，旧任务不需要改写快照。

新增接口：`POST /api/production/runs/{id}/person-preparation/retry`。该接口与视频任务的 `/resume` 分离，并在事务内拒绝已删除、已取消或已有云端视频任务的错误重试。

成功生成后的虚拟人物计数和“复制为草稿”会使用运行时解析的人物。模拟生成不会计入真实成功出片数。

## 验证和发布范围

最终验证结果记录在实施计划的执行记录中。测试采用临时数据库、本地媒体和受控服务响应，未使用生产凭据或提交付费视频任务。

当前改动位于独立本地分支 `codex/auto-virtual-person`，未部署。项目历史部署记录曾出现 AIGC 素材已 Active 但模型仍返回素材不可用，因此本地流程测试不能替代当前账号的真实出片验收。正式验收需在目标环境确认模型、项目和素材权限，并验证一条真实生成链路。
