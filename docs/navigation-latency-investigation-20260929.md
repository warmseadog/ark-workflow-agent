# 三个管理入口间歇性加载慢：2026-09-29 排查记录

范围：`/people`、`/admin/settings`、`/admin/users`。
生产版本：`20260929T032950Z-account-policy-timing`，访问入口 `https://118.196.7.195:8443`。

## 结论与边界

已重复复现一个主要触发条件：浏览器共享连接中存在大素材下载时，页面和小型 API 请求出现数秒等待；素材下载结束后，多数请求恢复至百毫秒。将素材放到独立浏览器上下文传输，同期目标页面的等待明显减少。结合 TCP 重传与代码中重复完整素材下载的证据，优先处理素材传输与页面/API 共用连接、重复下载造成的竞争。

不能据此认定每一次历史卡顿均来自同一因素。独立连接实验前后仍出现约 1.48 秒和 2.48 秒的个别尖峰。尚未测得云厂商配置带宽、链路丢包位置，也未进行生产优化或发布。服务器健康接口正常只能排除当时的整体事件循环阻塞，不能单独排除特定路由中的所有竞争。

同一轮并行采集 60 次服务器本机健康请求，最大 2.73 ms；独立公网 HTTP 连接大多约 19–21 ms，最大 516.2 ms。目标浏览器共享连接同时出现秒级等待，支持传输竞争判断。

独立连接实验期间服务器健康采样最大 4.26 ms；媒体 8 MiB 传输总耗时 31.38 秒，目标页面仍在 0.10–0.46 秒内可用。实验前后仍有零星慢样本，不能宣称问题已解决。

- 初始 TCP 快照：当前客户端到 8443 的连接累计发送 45,394,740 字节，累计重传 4,619,520 字节。该比值为累计重传字节占比，不是网络丢包率。
- 实验连接也观察到明显重传；未更改服务器网络或带宽配置。
- 真实 Chrome 访问日志中，返回制作台时反复读取约 4.56 MiB、5.13 MiB 的素材，另有多笔视频 Range 读取。
- 当前服务器 CPU 基本空闲、约 7 GB 可用内存、磁盘使用率 34%，本次未发现服务崩溃重启。

- `app/static/production.js:775` 附近：恢复草稿时并行完整读取视频、人物图、衣服图与其它参考素材。
- `app/static/production.js:865` 附近：进入制作台会恢复最近草稿，因此反复返回制作台会反复触发完整素材读取。

- `app/static/users.js` 末尾：登录状态 → 用户列表 → 任务与审计，传输延迟会沿前置依赖累加。

## 优先修复方向

1. 恢复草稿优先使用服务端素材 ID、元数据和预览 URL，避免为了显示已有素材而重新下载完整文件；需要编辑原始字节时才下载。
2. 离开制作台时取消已无用途的读取请求，停止不再使用的预览传输；保留现有未保存内容保护。
3. 隔离媒体传输与管理页面/API 的连接，结合现有鉴权设计选择独立媒体入口；不能简单公开私有素材。
4. 减少不必要的首屏配置请求，并为登录校验提供明确超时与可重试状态。它能改善故障反馈，但不能替代前述传输优化。

不建议将升级 CPU/内存作为首要措施；现有证据没有支持算力不足是本次主要瓶颈。
