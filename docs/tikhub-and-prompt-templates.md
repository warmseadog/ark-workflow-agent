# 分享链接与提示词模板

制作页面的参考视频卡片直接展示「粘贴视频链接」输入区，无需展开；可粘贴链接或完整分享文案。支持小红书、抖音、快手、B 站。
本地识别不调用 TikHub。输入后点击「导入视频」或按回车，服务端会解析并下载作品，自动在上方参考视频框显示预览；Shift+Enter 可换行。
加载中会显示状态并防止重复提交；解析或下载失败会显示原因，可再次确认重试。
成功导入后，视频素材保存到当前用户的草稿，刷新后可以恢复；后续打码和生成复用该素材，不再重复解析链接。
先确认导入视频，再进行打码预览或生成。上传、更换、移除视频后，链接输入框仍保持可见。
一次提交一个作品；多个不同平台链接会提示拆开提交，重复链接会去重。

## TikHub 配置

在链接输入区展开「链接解析设置」，输入 TikHub API Key 并保存。
也支持通过服务端环境变量 TIKHUB_API_KEY 配置。页面保存的配置优先；清除密钥会禁用环境变量回退，需重新保存才能使用。
密钥保存在 storage/local-preferences.db，不回传前端，不发送给媒体 CDN。
「已配置」仅表示已保存密钥，不表示已验证账户余额或权限。
平台解析失败会报告错误，不会回退到浏览器 Cookie 下载。其他 HTTP 视频链接仍走现有 yt-dlp 路径。

## 使用的官方接口

以 https://api.tikhub.io/openapi.json 为参数依据，核对日期 2026-09-24。

- 抖音：GET /api/v1/douyin/app/v3/fetch_one_video_by_share_url，share_url。
- 小红书：GET /api/v1/xiaohongshu/app_v2/get_video_note_detail，share_text（保留 xsec_token 等参数）。
- 快手：GET /api/v1/kuaishou/web/fetch_one_video_by_url，url。
- B 站：GET /api/v1/bilibili/web/fetch_one_video，bv_id；
  然后 GET /api/v1/bilibili/web/fetch_video_playurl，bv_id 和 cid。

B 站支持 b23.tv 短链接、BV 详情页和 p 分 P 参数；AV 页面尝试从网页元数据读取 BV 号。
分离音轨在本机通过 FFmpeg 合并，分段视频按顺序合并为 MP4。
图文笔记、直播、不可访问作品、鉴权和下载失败都会显示错误。
下载总大小沿用 MAX_UPLOAD_MB，外部跳转拒绝本地/私有网络目的地址。

### Fake-IP 代理兼容

可以保持代理的虚拟 IP 模式开启。检测到域名解析到 198.18.0.0/15 时，项目通过固定的 HTTPS 公共 DNS（AliDNS）查询真实公网 IPv4，再固定连接该公网 IP；HTTPS 仍校验原视频域名的证书并保留 SNI 与 Host。普通公网解析沿用原下载路径。
每次跳转仍重新校验；本地/私网地址、直接填写虚拟 IP、公共 DNS 返回非公网地址都会拒绝。公共 DNS 不可用时显示明确错误，不会直接放行虚拟网段。不修改系统 DNS 或代理设置。

### 方舟生成前的存储配置

使用火山方舟时，三类素材之外还需提供它能读取的视频地址。启用已填写的 TOS 后，生成时自动上传打码视频并提供临时签名地址，此时工作台公网地址可留空。TOS 连接测试只检查桶访问，实际上传和下载权限在任务执行时验证。

## 提示词模板

展开「提示词与模板」可选择、改名、编辑内容、保存修改、另存、删除。
默认四个模板只初始化一次，删除后不会在刷新或重启时重新出现。
模板存在 storage/local-preferences.db，未保存的编辑草稿留在当前浏览器。
模板 API 仅允许本机同源访问，当前应用没有多用户账户，所有本机用户共享模板。
数据库损坏或磁盘写入失败不会用默认模板覆盖已保存数据。

## 验证边界

自动测试模拟 TikHub 响应，不消耗额度。真实平台数据结构及作品可用性最终需使用有效 Key 和公开样本联调。
